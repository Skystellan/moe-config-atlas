每行一个配置，每格是一层 token mixer，从第一层排到最后一层。格子越高，这一层的 KV 缓存随上下文涨得越多：全局和稀疏注意力最高，滑窗和分块一半，线性注意力、Mamba 和短卷积的状态大小固定，最矮。悬停看每一层，点型号加入并排对比；按归一均分或单个榜单排序，可以看榜单上靠前的模型用的是什么层。随上面的筛选变化。

口径

E / k / s
路由专家数 / 每 token 选中的路由专家数 / 共享专家数。逐层不同的模型取均值或众数，表中标 ≈。
E/k
路由稀疏度，只看路由专家。
专家激活比 A
(k + s) / (E + s)，把共享专家也算进去。
参数激活比
激活参数 / 总参数，两者取自模型卡或技术报告（config 里没有）。
G
2d / dexpert，d 是隐藏维度。和标准 FFN 宽度 8d/3 比，G≈2.7 相当于"一个专家 = 一个 dense FFN"。
d/L
宽深比：隐藏维度除以 token mixer 层数（注意力、线性注意力或 Mamba 层）。LongCat 每层有两个注意力子层，按两层计。
注意力宽度比
全局注意力层的 query 头数 × 每个头的 Q·K 维度，再除以 d_model。头数 × 头维 = d 的 Llama 式设计为 1；MLA 的 Q·K 维度是不加位置的部分加 RoPE 部分（DeepSeek V3 是 128 + 64），DeepSeek V4 系每头 512 维，所以到 6.4–9.1。比值越大，注意力相对残差流越宽。
Q/KV
全局层每个 KV 头对应几个 query 头（GQA 的分组大小），越大 KV cache 越省。MLA 缓存的是压缩潜向量，不适用。
RoPE 维度占比
全局层每个头里加 RoPE 的维度比例。1 是全部维度；1/4、1/3 之类是部分 RoPE，其余维度不带位置；0 记为 NoPE，位置信息交给滑窗层、分块层、线性层或 Mamba 层，括号里是例外（Inkling 改用学到的相对位置 logit；North Mini Code 的第一个全局层是 dense 层，仍加 RoPE）。Mistral Large 4 每 4 层有一层不加 RoPE，NoPE 列记为“18/72 层”。MLA 按 RoPE 维度 / Q·K 维度算。
全局注意力层占比
KV 缓存随上下文增长的层（full、MLA、DSA、稀疏或压缩注意力）占全部 token mixer 层的比例。线性注意力、Mamba、短卷积的状态大小固定，滑窗层和 Llama 4 的分块层只缓存窗口或块内的 token。
KV cache / token
上下文足够长时每多一个 token 要多存的 bf16 KV：全局层数 × 每层每 token 的 K、V 维度 × 2 字节。MLA 按 kv_lora_rank + RoPE 维度算；DeepSeek V4 的压缩层按压缩率摊到每个 token（CSA 每 4 个 token 存一条，HCA 每 128 个）。不含线性层状态、滑窗缓存和稀疏注意力的索引键；DeepSeek V4.1 改了压缩配置的写法，暂不计算。
注意力
按 config.json 里的层类型字段推断（layer_types、kda_layers、full_attention_interval 等），只数 token mixer 的种类和层数，细节以技术报告为准。
结构特征
按 config.json 的字段识别，config 里没有写的部分（比如 Qwen3 的 QK-norm、gpt-oss 的 sink、各家的路由打分函数）对照 transformers 5.21 和厂家仓库里的建模代码核对，规则在 scripts/hfconfig.py 的 ARCH 里。config 未公开或看不出的记为"?"，不计入采用率。
结构指纹
形状数值按全部配置的五分位上色，只表示在收录范围内的相对大小；格子里的值和全表一致。按厂家或档位汇总时，格子是用了该特征的配置数 / 该组配置数。
线性注意力
状态大小固定的 token mixer：Gated DeltaNet（GDN）、Kimi Delta Attention（KDA）、MiniMax 的 Lightning Attention、Mamba-2，以及 LFM2 的门控短卷积（表中记为“门控卷积”）。
稀疏注意力
每个 query 只看部分 KV：DeepSeek 的 DSA、LongCat 的 LSA（DSA 的 top-k 预算里固定留开头和最近的 token，并跨层复用索引）、Qwen3.8-Flash-Next 的 QSA、Step-5 的 CSA、MiniMax M3 的块稀疏、DeepSeek V4 的压缩注意力（CSA + HCA）。ERNIE 5.5 Flash 大部分层是 HCA，每 7 层一个 MLA+DSA 层，记为 DSA+HCA。
输出门
softmax 注意力层的输出乘一个由输入算出的门（Gated Attention，多数用 sigmoid，Laguna 用 softplus），每个头一个标量的记"逐头"，每个元素一个的记"逐元素"，config 没写明的记 ✓。线性注意力层自带的门不算。
Sink / QK-norm
Sink 是每个头一个可学习的 logit，让注意力可以"什么都不看"；QK-norm 是对每个头的 Q、K 做 RMSNorm（Llama 4 Scout 和 ZAYA1 用 L2 归一化，Scout 只在 RoPE 层用）。MLA 对低秩潜向量的归一化不算 QK-norm。
K=V / 跨层 KV / 索引复用
K=V：K 和 V 用同一个投影，只缓存一份。跨层 KV：后面的层直接读前面源层的 KV，自己不再存。索引复用：稀疏注意力的 top-k 选择由几层共用（IndexShare、跨层索引），省掉索引器的计算。
QKV 短卷积
softmax 注意力的 Q、K、V 先沿序列过一个因果深度卷积（Primer 提出）。Inkling 对 K、V 和两个子层的输出各加一个 4 抽头卷积；ZAYA1 的 CCA 在压缩的潜空间里对 Q、K 做卷积。线性注意力层里自带的短卷积不算。
长度缩放（SSMax）
全局层把 query 按位置的 log 放大，长上下文里注意力不被摊平（Scalable-Softmax）。Llama 4 叫温度调节，Beam、Inkling 也只用在不加 RoPE 的全局层；Mistral Large 4 每层都用，系数按头学习（记为“逐头可学习”）。
超连接
把残差流扩成 n 路并用可学习的权重混合（Hyper-Connections）；mHC 用 Sinkhorn 把混合矩阵约束成双随机矩阵；iHC 是 Hy4 的写法。
AttnRes
Attention Residuals：每层的输入由对前面各层（按块）输出的注意力加权得到，代替固定的残差相加。
残差门 / 后置 norm
残差门：子层输出和残差按逐通道的可学习权重相加（Muse Spark 是保方差的门，ZAYA1 是两边各一组缩放）。后置 norm：子层输出再过一次 norm，前后都有的叫三明治，只在残差相加之后的叫 Post-LN，A.X K1 只在 MoE 输出后加。
GatedNorm / 并行块
GatedNorm：RMSNorm 的输出再乘一个由它算出的低秩 sigmoid 门，格子里是秩。并行块：注意力和 FFN 读同一个输入，输出一起加回残差（Cohere）。
共享专家门
共享专家的输出再乘一个由输入算出的门：Qwen 系是单独的 sigmoid 门，Inkling 让路由器给共享专家也打分（"路由加权"）。
零计算专家
不做计算的空专家，路由选中它就等于这个 token 少算一个专家（LongCat 的零计算专家、ZAYA1 的跳过专家），格子里是个数。
路由
打分函数（softmax、sigmoid、sqrtsoftplus）、无辅助损失的专家偏置（按分位数更新的记"分位数"，只在训练时用、权重里没有的记"仅训练"）、先选组再选专家的分组路由、前几层按 token id 哈希分配专家的哈希路由。
FFN 激活 / 限幅
多数是 SwiGLU；Gemma 4 用 GeGLU，gpt-oss 和 MiniMax M3 用带限幅和偏移的 SwiGLU（SwiGLU-OAI），Nemotron 3 用 ReLU²，Kimi K3 用 SiTU。限幅是把 SwiGLU 的输出截到上限，括号里是只在部分层；SiTU 用 β·tanh(x/β) 软限幅。
MTP
多 token 预测模块的层数；config 没写的从权重索引里数 mtp 层（需申请访问的仓库读公开副本的索引），读不到的记"?"。
softcap
输出 logit 过 c·tanh(x/c) 的软截断，格子里是 c。
N-gram 记忆
用哈希过的 n-gram 查一张大嵌入表：Engram 和 Qwen3.8-Flash-Next 在中间层注入，LongCat 加在输入嵌入上。
设计细节对照
每个位置（注意力输出门、路由权重、残差相加、norm 等）列出收录模型里出现过的写法，公式按建模代码写；config 和代码都看不出的记为“细节未公开”。“相关工作”是论文或训练配置里的写法，收录的模型还没用。名单和匹配规则在 details.yaml，构建时检查每个模型都归到了某种写法下。
前沿技术追踪
名单在 techniques.yaml，每条有最早出处、独立实验的结果和链接。采用数由结构特征自动统计；config 看不出的技术（优化器、损失函数）只列技术报告里写明的，没有就留空，不靠猜。
config 来源
仓库需申请访问时，config 取自 transformers 里对应的默认配置或公开副本，存档在本仓库的 configs/ 下，并在表格详情里注明。
榜单分数
三个公开榜单的分数，用来给配置排序，每次构建时重新读取。ECI 是 Epoch AI 的能力指数（Epoch Capabilities Index），由 GPQA Diamond、SWE-bench Verified、HLE、FrontierMath 等几十项 benchmark 的成绩拟合成一个数，开源和闭源模型在同一把尺子上；Arena 是 arena.ai（原 LMArena）文本榜的分数，来自用户对匿名回答的两两投票，用的是默认的 style control 榜，更接近聊天体验而不是 benchmark；WebDev 是同一网站的 WebDev 榜，用户提一个做网页或小应用的需求，两个匿名模型各写一版，再投票选更好的那个，更偏代码和前端能力。榜单上的名字和每个配置的型号、仓库名和同配置的各个版本对上（规则在 scripts/bench.py，对不上的写在 bench.yaml），同一配置取最高分，并注明取自哪个版本：后续版本只换了后训练，架构还是这一个。分数只反映收录时的版本，小模型和地区性模型覆盖得少。三个榜的数据都按 CC BY 4.0 使用。Artificial Analysis 的智能指数没有收录：它的条款不允许把分数做成表格或数据文件公开。
归一均分
三个榜的尺度不同（ECI 大约 120–160，Arena 文本榜是 1300–1500 上下的 Elo 分，WebDev 榜也是 Elo 分但拉得更开，大约 1200–1700），收录的配置也不一样，所以先把每个榜换成标准分：（分数 − 均值）÷ 标准差，均值和标准差都按三个榜都有分的那些配置来算，只上了一两个榜的配置也就和同一组配置比。每个配置平均它有分数的那几个榜，最后把站内最高记 100、最低记 0。缺了某个榜的配置会标出来（如“仅 Arena”），它的均分只代表上了的那几个榜。哪个榜都没有的配置排在最后。
档位
按总参数：小 ≤ 50B，中 50–500B，大 ≥ 500B。
